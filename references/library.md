# 存档库规范

跑完一轮流程的成果存在这里，下次一句话复用。第一次写入前完整读一遍本文件。

## 先确认运行环境能不能写文件

这份规范假设你能读写本地文件。现实中这个 skill 可能跑在 Claude Code、Codex CLI、其他 agent 客户端，
也可能跑在根本没有文件系统的纯聊天网页端。首次需要存档时先判断：

- **有可用的文件读写能力** → 走下面的「根目录解析」；
- **没有** → 跳到本文末尾的「无文件系统时的退化」。

不要先宣布已经存好再发现写不了。

---

## 根目录解析

存档库放哪里由用户决定。**不要把绝对路径写死在文件里，也不要假定存在 `~/.claude/` 这类某个客户端特有的目录。**
按以下顺序确定：

1. 用户在当前对话里直接指定了路径 → 用它，并执行第 4 步记录；
2. 读指针文件（存的是存档库绝对路径，单行，UTF-8）。按顺序找第一个存在的：

   | 位置 | 适用 |
   |---|---|
   | `./.vrd-library-path` | 当前工作目录，项目级配置，优先级最高 |
   | `$VRD_LIBRARY` 环境变量 | 用户自己设的，直接当路径用，无需再读文件 |
   | `<客户端配置目录>/vrd-library-path.txt` | 当前客户端已存在的配置目录，如 `~/.claude/`、`~/.codex/`、`~/.config/<客户端>/`——**只用已经存在的那个，不要为了放这个文件新建客户端目录** |
   | `~/.vrd-library-path` | 以上都没有时的通用位置 |

   读到的路径已不存在 → 当作未配置，转第 3 步；
3. 都没有 → 第一次需要写盘时问用户一次（**只问这一次**，且不要在还没到写盘时机时提前问）：

   > 存档库放哪个文件夹？直接回复路径即可。

   等用户回复，不要自行选一个地方就建；
4. 确定后把绝对路径写回上表中**当前环境可写的最靠前位置**，以后不再问；根目录不存在就创建。
   指针写不了（没权限等）也不阻塞本次存档，但要告知用户：下次得再说一次路径。

路径分隔符跟随当前系统，Windows 用 `\`，macOS/Linux 用 `/`；写入指针的始终是绝对路径。

用户说「换个地方存 / 存档库改到 X」→ 更新指针，并问一句是否把已有 preset 一并迁过去；同意就整体移动目录再更新指针，不同意就只改指针、老的留在原处。

下文用 `<存档库>/` 代指这个根目录。缺少的子目录和 `index.md` 在首次写入时创建。

### 存档库自带身份

`index.md` 开头写一行 `> 根目录：<绝对路径>`。这样即使指针丢了、或者库被整个拷到别的机器，
用户把文件夹拖给你时你仍能认出这是一个存档库；路径对不上就以实际所在位置为准并更新这行。

## 目录结构

```
<存档库>/
  index.md                      # 总目录，一行一个 preset
  SP1-夜景梦感半写实/
    preset.yaml                 # 属性
    brief.md                    # 当时的确认单原文
    notes.md                    # 效果反馈（可选）
    refs/
      A-subject.png             # 用户上传的参考图原件
      B-style.jpg
      C-pose.png
    out/                        # 该 preset 生成过的成品（可选）
      01.png
  SP2-胶片黄昏人像/
    ...
```

目录名 = `<编号>-<中文名>`。编号取 `SP` + 当前库内最大序号 +1，扫 index.md 得出；库为空则从 SP1 开始。中文名里出现 `/ \ : * ? " < > |` 一律替换成 `-`。

---

## index.md 格式

```markdown
# 视觉参考存档库

| 编号 | 名称 | 范围 | 参考图 | 建立日期 | 一句话特征 |
|---|---|---|---|---|---|
| SP1 | 夜景梦感半写实 | style | 2 | 2026-09-26 | 低反差柔焦，暖橙人物光配冷蓝夜景 |
| SP2 | 胶片黄昏人像 | full | 3 | 2026-10-02 | 逆光颗粒，黑位抬升，怀旧抓拍 |
```

每次新增或改名都要同步更新这张表。用户问「我之前存过哪些」直接读它，不要去逐个目录翻。

## preset.yaml

```yaml
id: SP1
name: 夜景梦感半写实
scope: style                  # style | subject | full
created: 2026-09-26
updated: 2026-09-26
summary: 低反差柔焦，暖橙人物光配冷蓝夜景，像记不真切的梦
aliases: [夜景梦感, 那个朦胧夜景]   # 用户口头叫过的说法，便于模糊匹配

style:                        # scope 含 style 时必填，字段见 extraction-schema.md
  medium: 半写实动漫 + 照片级皮肤/头发
  realism_level: 动漫化眼睛比例 + 写实皮肤与光照
  optics: 柔焦 / 高光扩散 / 浅景深 / 大块散景 / 轻微光晕
  contrast: 低反差，黑位抬升
  palette: 暖橙人物光 + 冷蓝环境
  texture: 细微胶片颗粒，无数字锐化
  mood: 安静、私密、怅然

subject:                      # scope 含 subject 时必填
  identity_anchors: 金发编发盘发 / 绿眼 / 深蓝蝴蝶结 / 二十岁上下
  is_real_photo: false
  ref: refs/A-subject.png     # 身份以此图为准，优先级高于任何生成图

outfit:                       # scope=full 时按需
scene:                        # scope=full 时按需
lighting:

refs:
  - file: refs/A-subject.png
    role: SUBJECT
  - file: refs/B-style.jpg
    role: STYLE

positive_constraints:         # Phase 7 的正向表述，存下来避免重推
  - 哑光的自然皮肤质感，保留毛孔和细微不均
  - 眼睛与主要五官保持全画面最清晰处

output:
  aspect_ratio: "16:9"
  count: 1
```

`scope` 决定复用时套用哪些维度，其余维度仍走 Phase 1–4 正常提取。

## 参考图的保存

**参考图必须连同存**。风格属性是文字近似，原图才是真正的锚点；复用同一人物时以 `subject.ref` 为准，优先级高于之前生成出来的任何图（Phase 2 一致性规则）。

- 文件名 `<参考图编号>-<角色小写>.<原扩展名>`，如 `A-subject.png`、`B-style.jpg`；
- 一图多角色时角色用 `+` 连接：`A-style+atmosphere.png`；
- 保存原件，不要压缩或转码；
- 拿不到可保存的原件时，在 `preset.yaml` 里写 `refs: []` 并加 `refs_missing: true`，同时在回复里明说这次参考图没能一起存、复用时要重新上传。

## notes.md

生成完用户给了反馈就追加一行，下次复用前先读：

```markdown
- 2026-09-26 出图偏亮，下次曝光压半档
- 2026-10-02 散景太大遮住了背景地标，收一点
```

复用时把这些已知修正**直接体现在新的确认单里**，不要让用户重复提同一个意见。

---

## 复用流程

1. 用户说「沿用 SP3」「用夜景梦感那套」「还是上次那个」→ 读 index.md 做匹配（编号 → 名称 → aliases → 模糊词）；
2. 命中唯一项：读 `preset.yaml` + `notes.md`，`scope` 覆盖的维度跳过提取；`refs/` 里的图作为该维度的视觉锚点一并带入生成；
3. 命中多项或完全没命中：列出最近 3 个（编号 + 名称 + 一句话特征）让用户选，**不要猜**；
4. 进 Phase 4，确认单开头标注沿用来源和被沿用的维度；
5. 用户要在存档基础上改 → Phase 5 增量修订 → 改完问「覆盖 SP3 还是另存？」，**默认另存新编号**，覆盖需用户明确同意，且覆盖前保留原 `preset.yaml` 为 `preset.yaml.bak`。

---

## 删改

- 改名：改目录名 + `preset.yaml` 的 `name` + index.md 那一行，三处同步；
- 删除：用户明确点名要删才删，删前复述「即将删除 SP3 夜景梦感半写实，含 3 张参考图」并等确认；
- 不要自动清理"看起来没用过"的 preset。

---

## 无文件系统时的退化

纯聊天网页端等环境下没有可写的本地目录，此时：

1. 把完整的 `preset.yaml` 以代码块输出给用户，建议他自己存成文件或留在对话里；
2. 明说参考图没能一并存，下次复用时需要重新上传；
3. 用户下次把这段 YAML 贴回来，就当作命中的 preset 用，直接跳过对应维度的提取；
4. 支持上传文件但不支持写回本地的环境，可以把整个 preset 打包成一个可下载的 zip 给用户自行保存。

**任何情况下都不要宣布“已存好”而实际上什么都没写。**
